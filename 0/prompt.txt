なお発生した問題の原因が判明した。↓
Devsy 1.23.0 の認証中継が、接続間で引き継がれない問題を実 VM で再現しました。

再現した流れは次のとおりです。

SSH 接続 A が credential server（12049）を起動。VM の Git はホストから認証情報を取得できる。
接続 B は「別の接続が提供済み」と判断し、中継の起動を見送る。
A が終了すると credential server が消える。B は接続したままでも中継を引き継がない。
helper の設定だけが残り、Git は認証情報を取得できず Username を要求する。
実装も、ポート使用中の場合は成功扱いで終了しており、所有していた接続の終了後に再取得する処理がありません。

今回の起動時にも同じ競合が起きたかは、当時のログがなく未確定です。 ただし、同じ VM・バージョンで同じ故障状態を再現でき、追加接続中は認証情報を取得できたため、ホストの認証情報不足は除外できました。

恒久対応は、Devsy 側で中継の所有接続が終了した際に、残る接続が再取得することです。アダプタ側でも SSH 接続だけでなく認証中継の稼働確認が必要です。

調査用接続は終了済みです。元の Orca 接続は維持し、コードは変更していません。
